**相似度逻辑**

- 形状相似度
  - 标准化：将多边形顶点平移到质心，按最大半径缩放到单位尺度（`normalize_polygon`）。
  - Hausdorff：双向定向距离取最大值（`directed_hausdorff`），相似度映射为 `1 / (1 + d)`，范围在 `[0,1]`。
  - Hu矩：将标准化多边形栅格化到 `500x500` 掩码，计算 `cv2.HuMoments`，做对数变换后取欧氏距离，再映射为 `1 / (1 + distance)`。
  - 组合：`shape_similarity = (hausdorff_sim + hu_sim) / 2`。
- 尺寸相似度
  - 面积比：`min(area1, area2) / max(area1, area2)`，范围 `[0,1]`。
- 方向相似度
  - PCA主方向：对顶点的协方差矩阵做特征分解，取最大特征向量为主方向。
  - 角度差：`angle_diff = arccos(|dot(dir1, dir2)|)`，映射为 `1 - angle_diff / (pi / 2)`，范围 `[0,1]`。
- 综合相似度
  - 加权线性组合：`overall = w_shape * shape + w_size * size + w_orient * orient`。
  - 权重来源：`config.py` 中的 `SHAPE_SIMILARITY_WEIGHT=0.4`、`SIZE_SIMILARITY_WEIGHT=0.3`、`ORIENTATION_SIMILARITY_WEIGHT=0.3`。
  - 唯一性评分：对每个多边形，`max_similarity` 和 `avg_similarity` 参与计算，`score = 0.7*(1-max) + 0.3*(1-avg)`。

**资源消耗评估**

- 时间复杂度
  - 相似度矩阵：`O(P^2)` 对比，`P` 为多边形数量。
  - 每对开销：
    - Hausdorff：`O(V1 * V2)`，顶点数多时较重。
    - Hu矩：栅格化 + `cv2.moments`（固定图大小，近似常数，但与掩码尺寸线性相关）。
    - 方向相似：PCA、`eig` 在顶点数上接近线性。
  - 经验值（CPU, 单线程）
    - `P=100, V≈50`：总对数约 4950，粗略 2–6 秒。
    - `P=300, V≈50`：对数约 45k，粗略 20–60 秒；建议并行。
- 内存
  - 相似度矩阵 `P×P` 浮点：`P=1000` 时约 8 MB；`P=5000` 时约 200 MB。
  - 多边形列表与掩码临时内存：和图像大小、顶点数、Hu矩掩码尺寸有关（`500x500` 的单张掩码约 0.25 MB）。
  - 可视化与中间结果保存会增加磁盘与峰值内存占用。
- 存储
  - 输出图与 JSON 报告：单图像通常在几百 KB 到几 MB；批处理成百上千张时建议定期清理或压缩。
- 并发与硬件
  - 当前实现为 CPU，SciPy/OpenCV 均可多线程；对 `calculate_similarity_matrix` 做进程池并行可线性加速到 CPU 核心数。
  - GPU 加速不在现有栈内；若数十万多边形级别，需算法层面降采样与筛分。

**优化与二次开发路线图**

- 算法层级
  - 顶点重采样：将轮廓点统一降采样到固定长度（如 `V=64`），降低 Hausdorff 耗时。
  - 早期筛分：尺寸相似度或方向相似度低于阈值（如 `<0.3`），直接不计算形状相似度。
  - Hu 矩降分辨率：掩码从 `500x500` 降到 `256x256`，对速度影响大、精度影响小。
- 工程层级
